## Descrição

Cria uma cobrança PIX. A VisePag gera o UUID da cobrança no backend e devolve no campo <code>id</code>. A cobrança vale 24 horas.

<Note>
  O campo <code>amount</code> é sempre enviado e devolvido em <strong>centavos</strong>. Por exemplo, <code>1000</code> = R$ 10,00.
</Note>

**Rate Limit:** 60 requisições/minuto

---

## Headers

<ParamField header="Authorization" type="string" required default="Bearer YOUR_API_KEY">
  Bearer token de autenticação. Formato: <code>Bearer YOUR_API_KEY</code>
</ParamField>

<ParamField header="Content-Type" type="string" required>
  Deve ser <code>application/json</code>
</ParamField>

---

## Body

<ParamField body="amount" type="integer" required>
  Valor em centavos. O mínimo é <code>500</code> (R$ 5,00) e o máximo <code>10000000</code> (R$ 100.000,00).
</ParamField>

<ParamField body="description" type="string" required>
  Descrição da cobrança, até 140 caracteres.
</ParamField>

<ParamField body="customerName" type="string" required>
  Nome do pagador, até 200 caracteres.
</ParamField>

<ParamField body="customerDocument" type="string" required>
  CPF (11 dígitos) ou CNPJ (14 dígitos) válido do pagador, só números.
</ParamField>

<ParamField body="customerEmail" type="string">
  E-mail do pagador.
</ParamField>

<ParamField body="method" type="string" default="pix">
  Método de pagamento. Hoje só <code>pix</code>. Se não for enviado, vale <code>pix</code>.
</ParamField>

---

## PIX

### Requisição

<CodeGroup>
~~~bash cURL
curl -X POST https://api.visepag.com/v1/payins \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 1000,
    "description": "Pedido #1234",
    "customerName": "João Silva",
    "customerDocument": "52998224725",
    "customerEmail": "joao@email.com",
    "method": "pix"
  }'
~~~

~~~javascript Node.js
const response = await fetch('https://api.visepag.com/v1/payins', {
  method: 'POST',
  headers: {
    Authorization: 'Bearer YOUR_API_KEY',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    amount: 1000,
    description: 'Pedido #1234',
    customerName: 'João Silva',
    customerDocument: '52998224725',
    customerEmail: 'joao@email.com',
    method: 'pix'
  })
});

const charge = await response.json();
~~~
</CodeGroup>

### Resposta 201 Created

<ResponseField name="id" type="string">
  UUID da cobrança, gerado pela VisePag.
</ResponseField>

<ResponseField name="status" type="string">
  Status da cobrança. Na criação, <code>pending</code>. Veja [Status](/concepts/status).
</ResponseField>

<ResponseField name="method" type="string">
  Sempre <code>pix</code>.
</ResponseField>

<ResponseField name="amount" type="integer">
  Valor em centavos.
</ResponseField>

<ResponseField name="platformFee" type="integer">
  Taxa da VisePag, em centavos.
</ResponseField>

<ResponseField name="pixCopy" type="string">
  Código PIX copia-e-cola.
</ResponseField>

<ResponseField name="pixQrCode" type="string | null">
  Imagem do QR Code (PNG em base64), ou <code>null</code>. O copia-e-cola sempre vale sozinho.
</ResponseField>

<ResponseField name="expiresAt" type="string">
  Expiração em ISO 8601.
</ResponseField>

## Erros

| Status | Código | Descrição |
|--------|--------|-----------|
| 400 | <code>invalid_amount</code> | <code>amount</code> deve ser um inteiro positivo em centavos |
| 400 | <code>description_required</code> | <code>description</code> é obrigatória |
| 400 | <code>customer_name_required</code> | <code>customerName</code> é obrigatório |
| 400 | <code>customer_document_required</code> | <code>customerDocument</code> é obrigatório |
| 400 | <code>invalid_customer_document</code> | CPF ou CNPJ inválido |
| 400 | <code>invalid_customer_email</code> | E-mail inválido |
| 400 | <code>invalid_method</code> | <code>method</code> diferente de <code>pix</code> |
| 401 | <code>missing_authorization</code> | Header <code>Authorization</code> ausente |
| 401 | <code>invalid_api_key</code> | Chave de API inválida |
| 422 | <code>amount_below_minimum</code> | Valor abaixo de R$ 5,00 |
| 429 | <code>rate_limit_exceeded</code> | Limite de 60 requisições/minuto excedido |
| 502 | <code>provider_rejected</code> | A adquirente recusou a cobrança |
| 502 | <code>charge_creation_uncertain</code> | A adquirente não confirmou a criação |
| 503 | <code>provider_unavailable</code> | Adquirente indisponível no momento |
